# Badge design references

Research and direct image inspection were completed before the original template concepts were generated. These are publicly documented examples, with source quality and visual limitations stated explicitly. An observed badge is not evidence of a company's current internal credential specification. No official logo, credential image, security feature, or attendee photo is bundled in the app.

## Apple — WWDC24 attendee badge

**Source:** [Apple Newsroom: WWDC24 highlights](https://www.apple.com/newsroom/2024/06/wwdc24-highlights/), Apple's official event photo collection. [Attendee photo](https://www.apple.com/newsroom/images/2024/06/wwdc24-highlights/article/Apple-WWDC24-event-photos-attendee-240610_big.jpg.large.jpg).

**Verified:** the photograph is published by Apple for WWDC24 and shows an attendee wearing the event badge.

**Observed:** a tall blue pass, dominant stacked WW/DC/24 event lettering, and a contrasting white lower strip for attendee information. The event mark carries the strongest hierarchy; personal information occupies a smaller zone.

**Lesson used:** separate event identity and personal information with clear zones; use one large visual anchor and strong contrast. The photo is not sharp enough to identify the exact typeface or physical dimensions. No precise ratio or official font is asserted.

## OpenAI — DevDay 2023

**Source:** [Play Studio: OpenAI DevDay case study](https://play.studio/work/open-ai-dev). The case study contains badge photographs, including assets titled `DevDay_CaseStudy_49_IDBadges` and `DevDay_CaseStudy_50_IDBadgeDetail`.

**Verified:** the commissioned design studio documents its work for OpenAI's first DevDay. It describes the event identity, modular square motif, contrasting palette, and Söhne Mono logotype.

**Observed:** large serif attendee names contrast with tiny technical metadata. The event wordmark sits toward the lower left; small modular square details occupy corners. Bold background fields create variety without sacrificing text hierarchy.

**Lesson used:** contrast expressive name typography with restrained metadata; use aligned edges and small recurring geometric details. The logotype's documented font does not imply that every badge text field uses it. The implemented originals use local Georgia and Courier New rather than distributing those brand fonts.

## Microsoft — historical employee badge redesign

**Source:** [Ahmet Alp Balkan: New Microsoft employee badges](https://ahmet.im/blog/new-microsoft-employee-badges/). [Concept/adopted-design comparison image](https://ahmet.im/blog/images/2015/07/new-badges.png).

**Verified:** this first-person designer account describes a design that Microsoft adopted in 2015 and includes a Microsoft Design post. It is historical evidence, not a current badge specification.

**Observed:** the left image is the author's initial concept; the right image is the adopted design shown in the post. The latter has a colored upper portrait area, a circular portrait, and a white lower information area, with left-aligned name text and the Microsoft wordmark near the bottom.

**Lesson used:** keep brand, identity, and supporting details in deliberate zones; reserve enough quiet space for names. The article itself questions whether the original ratio carried through, so no exact official dimensions are claimed. The original templates do not copy the employee-photo or credential structure.

## Google — I/O 2026 press badge

**Source:** [Android Central: Google I/O 2026 live coverage](https://www.androidcentral.com/phones/live/google-i-o-2026-live-blog-android-17-android-xr-glasses-and-all-the-gemini-ai-news). [Credited badge photo](https://cdn.mos.cms.futurecdn.net/riDBCfEQkYqScXcpjEKbVd.jpg), credited to Derrek Lee / Android Central and identified in the coverage as a press badge.

**Verified:** a named journalist's event coverage supplies the photo and badge context. This is press documentation, not Google's design specification.

**Observed:** the visible face is dark navy, with a small #GoogleIO label near the top and a large multicolored Android/globe graphic. A small code is partly visible near the bottom, obscured by a hand. The design puts an event illustration ahead of text.

**Lesson used:** a dark field can support a single energetic color graphic with restrained branding. This is a reference for the pictured branding face; it does not establish the layout, typography, or hierarchy of an unseen attendee-name face. Spectrum uses original orbital ellipses, not Google's graphic.

## Anthropic — Code with Claude 2026, San Francisco

**Source:** [Kevin B. Ridgway's firsthand event recap](https://program247365.github.io/code-with-claude-2026-sf-recap/) and its [event photo](https://program247365.github.io/code-with-claude-2026-sf-recap/photos/IMG_1126.jpg). [Official Code with Claude page](https://claude.com/code-with-claude) corroborates the event identity.

**Verified:** the recap is explicitly unofficial and credits its photos to Kevin B. Ridgway. The badge attribution relies on that firsthand event context and the visible Code with Claude branding. The official page corroborates the event, not the exact photographed badge design.

**Observed:** a pale, tall badge partly covered by plush toys, with dark serif name typography, smaller company information, an event label near the lower left, and branching dark graphics toward the lower right.

**Lesson used:** a warm neutral palette, expressive serif names, and fine organic artwork can make a technical event feel approachable. Occlusion prevents reliable measurement of the complete badge and exact proportions. The exact typeface is not identified from the photo.

## Translation into original designs

These references supplied general principles: hierarchy, zoning, typographic contrast, deliberate negative space, and one controlled graphic idea. They did not supply traceable badge artwork or replicas.

| Original | Reference principles developed into a new composition |
| --- | --- |
| Editorial | Serif/small-mono contrast, warm paper, original orange corner and baseline |
| Signal | Event-scale graphic, strong dark/light contrast, original cropped blue arcs |
| Modular | Modular identity language developed into a lime rail, lilac block, and asymmetric labels |
| Contour | Warm neutrals and organic linework with a new branching composition |
| Spectrum | Colorful event artwork on dark ground, with original crossing orbital ellipses |
| Executive | Clear corporate zones, a new vertical band, and a compact role capsule |
| Split | Strong separation of event and attendee zones in a forest/sage horizontal layout |
| Studio | Editorial serif hierarchy, centered name, and an original quarter-circle sun |
| Vector | Event energy expressed through an original diagonal field and mint dividing line |
| Index | Technical metadata hierarchy expressed through a distinct ruled information grid |

All ten use fictional HORIZON branding and fictional attendee data. There are no official company logos, QR/barcodes, access permissions, or security claims. Font selections and 2:3 / 3:2 canvas proportions are original implementation choices. Public reference photos remain at their source URLs and are not redistributed in the ZIP.
